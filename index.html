Design Comparison

Where Chainvet is designed to differ.

Smart contract scanners often trade depth, compiler compatibility, runtime cost, or finding structure against each other. This section shows the product choices Chainvet makes to reduce those tradeoffs.

Hybrid evidence

Multiple signals, one finding workflow.

Single-layer tools can produce useful signals, but evidence may stay fragmented. Chainvet is designed to coordinate static planning, runtime traces, and solver assistance before findings are surfaced.

Common scanner shapeOne analysis layer reports independently, which can leave exploitability and path context unclear.
Chainvet directionA hybrid loop lets detectors guide runtime exploration, while solver assistance helps investigate stalled or narrow branches.

Parser recovery

Analysis should degrade gracefully.

Real repositories are not always compiler-clean: imports move, versions differ, and partial files appear during development. Chainvet keeps a fallback parser path so scans can still produce useful structure.

Compiler-bound workflowA single frontend failure can stop the scan before detectors see the source.
Chainvet directionPrefer compiler structure, then fall back to recovered Solidity structure when compilation is not available.

Pipeline

Hybrid analysis is the advantage.

Our engine runs multiple verification layers in a single pass. When compiler configurations fail, a robust AI fallback parser continues scanning automatically to prevent workflow interruptions.

01 / Detector layer

Compiler-aware structure first.

Chainvet starts with Solidity structure, compiler metadata, and fallback parsing so later checks have a consistent view of contracts and functions.

fallback: parser hints
